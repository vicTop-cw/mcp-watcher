## 3. 项目简介

mcp-watcher 是一个用 MoonBit 实现的 **AI 工作区自治运行时**（Autonomous Runtime）。核心思路是把「AI 工作区里反复出现的文件管理琐事」收敛为一份**声明式规则**（"当什么发生，做什么"），由后台常驻的守护进程沉默地执行，从而**不占用你和 Agent 的每一轮对话**。它不是"通用的文件监控触发器"，而是带有**产物生命周期语义**的动作系统——临时文件何时清理、敏感产物如何加密、过期文件如何进回收站、Agent 跑出的中间产物如何被安全回收。

典型链路为：**声明式规则（.mcp-watch.json）→ 文件事件（rx monitor，native 走 Windows ReadDirectoryChangesW 内核事件）→ 两层匹配（事件 + glob → exclude 优先 → 条件 AND）→ 生命周期动作（TTL / trash / command / internal）→ 结果落盘（JSONL 可观测）**。规则支持热重载（规则文件变更后守护进程不停机加载新规则表），并内置**双门禁**（动作准入 guard + 产物有效性 acceptance，schema v1.1，PLAN-gates.md）。

**当前状态（2026-11-20 本机实测）**：`moon check` 0 errors（36 条 Warning）；`moon test --target native` **222/222 通过**；`moon test --target js` **191/191 通过**；`moon test --target wasm-gc` 因 RX-MBT 依赖侧 fs_* 符号未绑定而编译失败（见第 11 章已知限制）；双进程 e2e（`tests/harness/`）存在守护进程监控缺陷（见第 11 章），事件链路已用独立探针证明 RX-MBT native 端可收到真实文件事件。

**诚实声明**：本项目核心代码自研（规则 DSL 模型与解析、两层匹配算法、TTL/trash/command 动作、guard/acceptance 双门禁纯函数判定、cron 表达式解析、CLI），但**非零依赖**——响应式内核（EventBus、文件监控、命令执行）复用兄弟项目 **vicTop-cw/RX-MBT@0.4.6** 与 **moonbitlang/async@0.22.9**。加密、mcp_tool_call、webhook 为诚实降级状态（见第 11 章），不把 no-op 包装成已实现。

## 4. 项目方向与通用性说明

**方向**：MoonBit 原生库 / AI 工作区自治运行时 / 声明式规则引擎 / 文件生命周期治理 / 后台守护进程

**通用性**：mcp-watcher 本质是一个**自治运行时框架**——不绑定任何特定 AI 产品。它提供的是「用声明式规则描述文件事件 → 自动执行生命周期治理动作」的通用能力，上层应用可以是任意需要"后台守候 + 规则治理"的 AI 工作区、CI 产物目录、个人数据目录。三层解耦：

- **规则层**：JSON DSL（schema_version=1）描述事件/glob/条件/动作，可读、可审查、可版本化；校验 fail-closed（`validate` 子命令）
- **事件层**：rx monitor 提供 native（Windows ReadDirectoryChangesW 内核事件）/ js（fs.watch）双后端，watch 包封装为统一 FsEvent 流
- **动作层**：TTL / trash / command / internal（EP-01a 四 op：reload_config / pause_watch / resume_watch / log_event）均为**有语义的生命周期动作**，guard/acceptance 双门禁是动作层的强化正交维度

任意一层可独立替换或增强而不影响其他层。

## 5. 预期使用场景

**场景 A：AI Agent 工作区自治（主场景）**

Agent 跑一轮任务会留下大量临时文件、中间产物、过期缓存。传统做法是"Agent 每轮对话里加一句清理指令"——既浪费一轮对话，又依赖 Agent 记得做。mcp-watcher 让规则在后台守护进程里自行完成：`create *.tmp → 记录 TTL → 到期进 trash`，Agent 全程无感。

**场景 B：敏感产物过期回收**

规则约定"输出目录里超过 7 天未修改的产物 → trash 回收"（TTL + trash 组合），避免敏感/过期产物长期滞留磁盘。加密能力因底层 rx 的 Fernet 为 `extern "js"`（node:crypto）在 native 不可做实，本项目**诚实降级**为返回可诊断错误，绝不写空密文破坏产物（待 rx 补 native crypto FFI）。

**场景 C：CI / 构建产物治理**

构建产物目录、测试中间目录的定期清理可写成规则（recursive 监控 + TTL 过期判定），由守护进程沉默执行，不阻塞 CI 主流程。

**场景 D：声明式命令自动化（command + 双门禁）**

规则命中事件后执行白名单内的 argv 命令（ExecPolicy 显式白名单，规则不会自动放行命令）；guard 前置校验（单命令必须 exit 0，`on_fail=skip/stop`），acceptance 后置验收（exit / stdout / artifact_glob），失败产物进入 TTL/trash 回收流。

## 6. 核心功能

| 模块 | 功能 | 说明 |
|---|---|---|
| 规则 DSL | JSON 声明式规则（schema v1.1） | `schema_version` / `watch_id` / `watch_dir` / `recursive` / `debounce_ms` / `allowed_programs` / `rules`，解析 fail-closed |
| 两层匹配 | 事件 + glob → exclude 优先 → 条件 AND | `create/modify/delete/rename/attrib/*` 事件；`age_seconds` / `file_size_gt` / `file_size_lt` / `mime_contains` / `not_modified_for` 条件 |
| 事件后端 | native: Windows ReadDirectoryChangesW（C 后台线程） | rx monitor 事件驱动；js 走 fs.watch；watch 包做统一 FsEvent 映射（Created→Create 等） |
| TTL 生命周期 | 产物注册追踪表 + 到期判定 | `product.expired` 生命周期事件 + 追踪表移除；可持久化 |
| trash 回收 | native 物理移入回收站 | 用 `moonbitlang/async/fs` 的 `mkdir`/`rename` 移入 `<watch_dir>/.trash/<name>.<ts>`，**零新增 C FFI**；js/wasm 无此 API，诚实返回"不支持" |
| command 动作 | argv 数组执行 + ExecPolicy 白名单 | 规则不会自动放行命令；拒绝事件落结果记录（JSONL），可 e2e 对拍 |
| 双门禁（guard） | 动作执行前环境准入 | 单命令必须 exit 0（与 command 同走白名单校验，绝不走 shell）；`on_fail=skip/stop`，失败记 `guard_fail` |
| 双门禁（acceptance） | 动作执行后产物有效性 | `expect_exit` / `stdout_contains`(AND) / `stdout_not_contains` / `stderr_not_contains` / `artifact_glob`；`accepted=false` 保留真实 exit 与输出，触发 `product.invalid` 进入 TTL/trash 回收流，**不做自动重试** |
| 热重载 | 规则文件变更不停机加载（EP-01d） | `fire_rules_reload` 按 id 热切换；坏 JSON 保留旧规则表并记录错误；`reload` 子命令直连 |
| internal 动作 | EP-01a 四 op | `reload_config` / `pause_watch` / `resume_watch` / `log_event` 直连调度器既有函数 |
| cron 解析 | cron 表达式解析与下次触发计算 | 纯逻辑、可测（cron 包） |
| CLI | validate / start / status / run / reload / help | `run` 支持 `--rules/--watch-dir/--results/--ready/--stop-after/--debounce-ms/--once`；`stop` 为 P1 待实现（提示手动删除 pidfile） |
| 可观测 | 执行记录 JSONL 落盘 + 日志轮转 | ExecRecord（rule_id / event / path / action_type / exit_code / stdout / stderr）；bus 订阅 `*.*` 可观测全量事件 |
| 加密 | 诚实降级（不可做实） | rx 的 Fernet 原语是 `extern "js"`（node:crypto），native/wasm 返回空串；本项返回可诊断 Err，绝不写空密文破坏产物 |
| mcp_tool_call / webhook | 扩展位 EP-01 | 返回可诊断错误（架构扩展位已登记，未实现） |

**质量保障**：单元与集成测试覆盖规则解析 fail-closed、两层匹配、guard/acceptance 纯函数判定（含"guard 非 0 + on_fail=skip → 动作零执行、guard_fail 事件在位"、"acceptance 不过 → 动作真实执行但 acceptance_failed 在位"等组合场景）、热重载（规则增删、坏 JSON 回退、reload_config op 回调）、ExecPolicy 白名单拒绝、RX-MBT 探针（R2/R3：native 事件可达性、白名单策略）。`moon test --target native` **222/222**、`--target js` **191/191**（2026-11-20 本机实测）。

**迭代历程**：项目经历"架构提案（fist-mbt）→ 设计决议（workbuddy/plan）→ 脚手架落地 → 接入 rx-mbt（R1~R4）→ TTL/command/trash 落地 → schema v1.1 双门禁 → 热重载 EP-01d → internal 注册表 EP-01a"等阶段；门禁从早期快照（native 21/21）迭代至当前读数（native 222/222、js 191/191）。

**已知限制**：
1. **守护进程监控缺陷（e2e 未通过）**：rx 的 `watch_folder_native` 轮询循环使用**线程级 `Sleep()`**（moonbit_sleep_ms，fs_native_stubs.c），在 MoonBit 协作式 async 单线程下**首个被调度的 watch 订阅任务永久独占执行线程**。`run_daemon` 在规则文件目录不在 `watch_dir` 覆盖范围时会补监控规则文件目录（第二个 watch 任务），该任务永不获得调度 → `watch_dir` 事件无人监听 → 结果记录为空。已用双目录探针确证（仅先启动的 A 目录事件到达，B 目录事件零到达）。**规避**：将规则文件置于 `watch_dir` 内（不触发补监控）；**根治**：rx monitor 轮询改 async 级 sleep，或仅保留单个监控任务（本项目计划在 P1 修复，修复后再复跑 e2e）。
